# Contribution Workflow

1. Create or assign an Issue before substantive work starts.
2. Create a short-lived branch from the latest `main`.
3. Make focused commits with meaningful messages.
4. Push the branch and open a Pull Request.
5. Link the PR to the Issue.
6. Both team members other than the author perform meaningful review.
7. Address requested changes and re-request review where needed.
8. Merge only after two approvals and all conversations are resolved.
9. Delete the merged branch.
10. Keep evidence progressive; do not bulk-upload reconstructed work before assessment.

## Commit message examples
- `docs: add stakeholder conflict analysis`
- `req: add measurable availability NFR`
- `risk: prioritise deployment environment risk`
- `gov: add team working agreement`
- `trace: link FR-004 to stakeholder and acceptance criteria`

## Review expectations
A review should consider correctness, requirement alignment, traceability, maintainability, security/privacy, test implications, dependencies, documentation impact, and downstream consequences.
