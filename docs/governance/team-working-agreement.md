## Task ownership
- Every substantive task is represented by a GitHub Issue.
- Issues have a named owner.
- Ownership means primary responsibility, not sole understanding.
- All members remain responsible for the complete project.

## Git and Pull Request workflow
- No substantive direct work on `main`.
- Work starts from current `main` on a task branch.
- PRs link the relevant Issue where practical.
- The two non-author members must review and approve.
- Self-approval is not accepted.
- Review comments must be addressed before merge.
- Force-pushes and deletion of `main` are prohibited.

## Review quality
Reviews consider requirement/acceptance alignment, correctness, consistency, traceability, security/privacy, tests, dependencies, documentation impact, and downstream consequences.

## Evidence
- Work is committed progressively.
- Bulk reconstruction before assessment is not acceptable.
- Important IDs remain stable.
- Baselined content is changed only through controlled change.

## AI use
- Material AI-assisted work is recorded.
- Important AI claims/output are independently verified.
- Secrets/credentials/confidential data are not supplied to unapproved AI tools.
- The student using AI remains responsible for understanding and defending the output.

## Conflict / delay handling
- Raise blockers early.
- Reassign work only by team agreement.
- Significant scope/schedule trade-offs are documented.
- Escalate unresolved disputes to the lecturer if needed.

## Baseline approval
All three members review the PED and linked controlled artefacts before sign-off.
